# HU-001 — Registro de tareas académicas

**Historia de usuario:** Como estudiante, quiero registrar una tarea con un título para organizar mis actividades pendientes.

## Criterios de aceptación (constantes entre los tres ensayos)

- **CA-01:** Al enviar `POST /tareas` con JSON `{"titulo":"Estudiar matemáticas"}`, se crea una tarea y se responde HTTP `201`.
- **CA-02:** Cada tarea creada incluye un identificador único, el título sin espacios exteriores y el estado inicial exacto `pendiente`.
- **CA-03:** Un título ausente, vacío, solo espacios o superior a 100 caracteres debe rechazarse con una respuesta de error HTTP `400` (sin crear tarea).
- **CA-04:** `GET /tareas` responde HTTP `200` y una lista que contiene las tareas creadas durante la ejecución.
- **CA-05:** Se incluyen pruebas que cubran al menos creación válida, rechazo de título vacío, rechazo de título demasiado largo y consulta de tareas.

## Alcance y restricciones

- Solo API, sin pantalla web.
- Guardar tareas en memoria durante la ejecución; no utilizar base de datos.
- No incluir autenticación, notificaciones, categorías, fechas límite, IA externa ni servicios en la nube.
- El alcance se considera cerrado: cualquier funcionalidad adicional se registra como posible **invención** hasta que sea aprobada.

## Pistas de verificación humana

Comprobar respuesta HTTP, estructura de datos, casos límite, pruebas ejecutadas, y correspondencia CA→archivo→prueba. No confundir código generado con código comprobado.
